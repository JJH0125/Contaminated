## 1. 시연 씬

### 만드는 법

1. Unity 메뉴 **Tools > 시연 씬 만들기**를 누른다.
2. `Assets/_Game/Scenes/Demo/`에 씬 7개가 생기고, Build Settings에도 들어간다.
3. 씬을 열고 플레이하면 타이틀을 건너뛰고, 그 단계에 맞게 꾸민 라운드가 바로 시작된다.

시연 씬은 Game 씬의 복사본이다. **Game 씬을 고쳤다면 메뉴를 다시 실행**해야 고친 내용이 시연 씬에 들어간다. 같은 이름의 시연 씬은 지우고 새로 만든다.

공통 설정:

- 시드는 1234로 고정되어 있다. 같은 씬을 열면 매번 같은 배치가 나온다. 바꾸려면 `Demo Scenario` 오브젝트의 Seed를 고친다.
- 덮어쓰는 것은 1라운드의 구성뿐이다. GameTuning 에셋은 바꾸지 않는다.
- 잡혀서 다시 시작해도 같은 준비를 다시 한다.

### 이번에 바뀐 동작 (알고 있어야 할 것)

- **계획을 세울 수 없는 목표는 건너뛴다.**

## 2. 나올 만한 질문과 답

### Q1. 우선순위가 같은 목표가 둘이면 어떻게 고르나요?

- 지금 목표는 100 / 75 / 60 / 50 / 1로, 일부러 간격을 두어 겹치지 않게 했다.
- 같아지면 **목록에 먼저 있는 목표**가 앞선다. 기본 목표가 먼저이고, 끼운 목표 부품은 그 뒤다. 정렬은 같은 값끼리 원래 순서를 지키는 `OrderByDescending`(안정 정렬)이다.
- 앞선 목표의 계획이 나오지 않으면 다음 목표로 넘어간다.

### Q2. 행동을 실행하는 도중에 세계가 바뀌면요?

- 0.4초마다 세계의 사실을 새로 모아 **처음부터 다시 계획**한다. 실행 중이던 행동은 그 자리에서 버리고 새 계획의 첫 행동으로 갈아탄다.
- 끊어도 안전한 이유: 행동의 실행(`Perform`)은 한 프레임에 한 걸음만 가고 끝났는지만 돌려준다. 걷던 경로는 이동 담당(`ChaserLocomotion`)이 들고 있어서, 같은 곳으로 가는 계획이면 그대로 이어 간다.
- 0.4초를 기다리지 않고 바로 다시 계획하는 사건:
  - 발견 신호를 받음
  - 목표 부품을 켜거나 끔
  - 같은 차원에서 새 발견 사건이 생김
  - 합류를 풂
  - 계획을 다 실행함
- 계획과 실제 사이의 틈도 막아 두었다. 잡는 순간에 "지금도 같은 차원인가, 차원 이동 직후의 유예가 끝났는가"를 한 번 더 확인한다. 그래서 0.4초 사이에 차원을 넘은 플레이어를 잡지 않는다.

### Q3. 계획은 어떤 방식으로 찾나요? 행동 수가 늘어나면 계산량은?

- **상태공간 A\***로 찾는다. 길찾기와 같은 A\*를 다른 문제에 적용한 것이다.
  - 노드: 사실들의 집합(`playerVisible=true` 같은 bool 값)
  - 간선: 행동. 조건이 지금 상태에 맞으면 효과를 덮어써 다음 상태를 만든다
  - g: 행동 비용의 합 (지금은 모두 1)
  - h: 목표와 다른 사실의 수
  - 방향: 지금 상태에서 목표 쪽으로 (전진 탐색)
- h가 과대평가하지 않는 이유: 목표마다 원하는 사실이 하나라 h는 0 아니면 1이고, 행동 비용은 1 이상이다.
- 목표 하나의 계획은 길어야 행동 2개이고, 행동은 8개다(기본 6 + 불 끄기 부품 2). 그래서 열린 목록은 `List.Sort`, 닫힌 목록은 없이 단순하게 했다. 무한 루프를 막으려고 500노드에서 멈춘다.
- 행동이 많아지거나 계획이 길어질 때:
  - 닫힌 목록이 없으므로 최악에는 (행동 수)^(계획 길이)만큼 늘어난다
  - 그때는 상태를 해시해 닫힌 목록을 두고, 열린 목록을 힙으로 바꾸면 된다. 길찾기(`Pathfinder`)는 칸이 수만 개라 이미 그렇게 했다
  - **지금 규모에서 단순한 쪽을 고른 것이지, 몰라서 안 한 것이 아니다**라고 답한다
- 실측: F4 위쪽의 평균·최대 ms와, F11 로그의 "살펴본 노드 수". (1번 할 일에서 잰 숫자를 쓴다)
- 함께 쓰이는 비용: 시야 검사는 0.2초마다, 싼 것부터 한다(거리 → 각도 → 레이캐스트). 계획은 적마다 0.4초마다다.

### Q4. 적 여러 명이 블랙보드에 동시에 쓰면 충돌은 없나요?

- Unity의 게임 로직은 **메인 스레드 하나에서 차례로** 돈다. 그래서 진짜 동시 접근은 없다. (소리를 코드로 만드는 오디오 스레드는 블랙보드를 쓰지 않는다)
- 순서 때문에 생길 수 있는 **논리적 충돌**은 이렇게 막았다.
  - **수색 지점**: 맡는 순간(`ClaimSearchPoint`) 주인을 적어 둔다. 같은 프레임의 다음 적은 그 지점을 가져갈 수 없다. 맡은 적이 사라져도 20초가 지나면 다른 적이 가져간다
  - **발견 사건 번호**: "아무도 보지 않다가 처음 본 순간"에만 오른다. 여러 적이 한꺼번에 봐도 사건은 하나이고 포효도 한 번이다
  - **지금 보고 있는 적**: 집합(HashSet)이라 중복이 없다
- 남은 한계: 소리 정보는 블랙보드에 하나뿐이다. 마지막 소리가 앞 소리를 덮어쓰고, 듣지 못한 같은 차원 적도 조사하러 간다. (Q6의 남은 일)

### Q5. FSM으로 했다면 무엇이 더 어려웠나요?

상태 수와 전이 수로 비교한다. 지금 행동은 8개다: Wander, MoveToSound, SearchSoundArea, MoveToSignal, SearchSignalArea, ReachPlayer, MoveToFire, Extinguish.

FSM이라면 우선순위를 반영한 전이를 사람이 모두 적어야 한다. (직접 센 값이라 대략이다)

| 전이의 종류                                    | 개수      |
| ---------------------------------------------- | --------- |
| 플레이어를 봄 → 추격 (추격 말고 모든 상태에서) | 7         |
| 신호를 받음 → 합류 (더 낮은 상태에서)          | 5         |
| 켜진 불 → 끄러 감 (더 낮은 상태에서)           | 3         |
| 소리 → 조사 (배회에서)                         | 1         |
| 차례 진행 (가기 → 둘러보기 → 배회 등)          | 7         |
| 놓침 → 다음으로 높은 상태                      | 4         |
| **합계**                                       | **약 27** |

- **불 끄기를 넣을 때의 차이**
  - FSM: 상태 2개가 늘고, 기존 상태들에 들어오고 나가는 전이 약 10개를 손대야 한다
  - GOAP: 목표 1개와 행동 2개(각각 조건과 효과)만 더했다. **기존 적 코드는 한 줄도 고치지 않았다.** 3번과 4번 씬이 그 증거다
- **GOAP의 비용**: 계산이 더 든다(Q3). 행동이 무엇을 할지 바로 보이지 않아 디버그 표시(F4, F11)가 필요하다.

### Q6. 아직 안 된 건 뭔가요?

숨기지 말고 "예정"으로 말한다.

- **소리 기억을 적별로**: 지금은 블랙보드에 소리가 하나뿐이다. 그래서 듣지 못한 같은 차원 적도 느린 속도로 조사하러 간다
- **놓친 자리 수색**: 수색 지도는 포효를 받고 합류한 적만 쓴다. 직접 보다가 놓친 적도 쓰게 할 예정이다
- **차원 이동 도착 소리**: 감지 유예(1초) 중에도 바로 전달된다
- **던진 돌 충돌**: 다른 차원 전용 장애물의 보이지 않는 충돌체에 부딪히고, 바위와 나무는 뚫고 지나간다
- **재의 적 애니메이션**: 발각 때 고개 돌리기, 잡을 때 팔 벌려 껴안기(Mixamo)는 연결할 자리만 만들어 두었다. 잡을 때 연출의 세기는 아직 플레이로 다듬는 중이다
- **차원별 지형**: 벽과 길찾기는 차원별로 나뉘었다. 지형 자체를 나누는 일은 그 뒤다

※ 받아 둔 제안의 "재의 적 포효 끄기"는 **이미 되어 있다**(Fake 적 `canRoar = false`). 남은 일로 말하지 않는다.

### Q7. (추가) 적은 플레이어의 차원 이동을 어떻게 받아들이나요?

- 적은 차원 이동을 이해하지 못한다. 같은 차원이어야 보고 잡을 수 있으므로, 적에게는 플레이어가 **갑자기 사라진 것**이다.
- 보던 적은 "놓침"을 보고하고, 마지막 위치를 단서로 남긴다. 경계는 바로 풀리지 않고 Alerted → Suspicious → Calm으로 서서히 내려간다. 그래서 금방 돌아오면 위험하다.
- 넘어간 직후 1초는 어느 적에게도 감지되지 않는다. 반대편에 적이 서 있는지 알 방법이 없어서 생기는 억울한 죽음을 막는다.
- 불 붙는 소리만 차원을 넘는다. 그 밖의 소리는 같은 차원의 적만 듣는다. 이 규칙은 블랙보드가 아니라 **누가 소리를 받는지**(`SoundEmitter`)에서 정한다.

### Q8. (추가) 두 차원의 길찾기는 어떻게 나눴나요?

- 격자를 두 개 만들지 않았다. **칸 하나에 Real 막힘 수와 Fake 막힘 수를 따로** 센다.
- 적은 자기 차원 기준으로 "이 칸을 지날 수 있는가"를 묻는다. 봉인된 관문은 Real만, 웅덩이는 Fake만 막는다.
- 장벽이 생기거나 사라지면(불을 켜서 관문이 타는 등) 격자 버전이 오르고, 그 뒤로 적이 경로를 다시 찾는다. 5번 씬이 이것을 보여 준다.
